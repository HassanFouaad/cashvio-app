## What are Roles?

A **role** defines what a team member can see and do in Cashvio. Each role has a set of **permissions** that control access to different features. For example, a "Cashier" role might only have permission to create orders, while a "Manager" role might have full access.

Each team member has **one role in your business**. Choose their role, then choose where they can use it: **Business-wide access (all stores)** or specific **Assigned stores**. The same role applies to every selected store.

For example, a cashier working in two branches has one **Cashier** role with both stores selected. For mixed duties, create one custom role with the permissions the person needs.

## How Permissions Work

Cashvio has fine-grained permissions in the format *action : resource*, grouped by resource. The main groups are:

| Resource | Available Permissions |
|----------|-----------------------|
| **Orders** | View, Create, Edit, Cancel |
| **Products** | View, Create, Edit, Delete |
| **Categories** | View, Create, Edit, Delete |
| **Customers** | View, Create, Edit, Delete |
| **Inventory** | View, Adjust, Transfer, Edit reorder point |
| **Payments** | View, Create, Edit |
| **Suppliers** | View, Create, Edit, Delete |
| **Purchase orders** | View, Create, Edit, Delete, Approve, Receive, Cancel |
| **Returns** | View, Create, Edit, Approve, Reject, Cancel |
| **Refunds** | View, Create, Process, Cancel |
| **Coupons** | View, Create, Edit, Delete |
| **POS Devices** | View, Create, Edit, Delete |
| **Cash Registers** | View, Create, Edit ([cash sessions](/docs/orders/cash-sessions)) |
| **Cash sessions** | View totals, Open, Close, Record cash in/out |
| **Cash drawer** | Open without a sale |
| **Cash session history** | View |
| **Users** | View, Invite, Edit, Deactivate, Assign role |
| **Roles** | View, Create, Edit, Delete |
| **Stores** | View, Create, Edit, Delete |
| **Business** | Business-level permissions |

<Callout title="Note">
When you grant any action on a resource, its **View** permission is added automatically, because you can't edit what you can't see.
</Callout>

## Scoped assignments and selected store

Operational pages (orders, inventory, POS, online store settings) evaluate permissions in the **selected store** context. A cashier assigned to Store A has no access to Store B unless you also select Store B.

**Business-wide access (all stores)** applies across current and future stores. Otherwise, access applies only to the stores you select.

A team member assigned to several stores works in all of them. Lists such as catalogue discounts, product reviews, store prices, product imports and store visits include every store where they hold the permission. Actions such as transferring stock work between any two of their stores.

**Business Admin** always has business-wide access. At least one active administrator must remain; the portal blocks changes that would remove the last active admin.

### Passing access on

You can only give out access you hold yourself, with the same reach:

- When you create or edit a role, you can include only permissions you hold business-wide.
- When you assign a role, you need all of its permissions business-wide for a business-wide assignment, or in that store for a store assignment.
- Creating a new store needs business-wide access to stores.
- Coupons and integrations follow their store: a team member with store-level access sees and manages only the coupons and integrations of their own stores.

## How Roles Affect the Interface

When a user logs in, their assignments determine:

- **Which sidebar menu items they see**: Their role determines the available pages; store-bound actions respect their assigned stores.
- **Which actions they can perform**: Buttons like "New Sale" or "Delete Product" only appear when the permission holds in the current store context (or tenant-wide when no store is required).
- **Which Dashboard quick actions appear**: Only actions the user is allowed to perform are shown.

<Callout title="Important">
**Business Admin** includes business administration and POS access. A Business Admin does not need an additional Cashier role. Changing a user's role replaces their previous role.
</Callout>
